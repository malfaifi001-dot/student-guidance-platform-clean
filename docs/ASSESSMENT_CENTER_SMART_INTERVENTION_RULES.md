# Assessment Center - Smart Intervention Rules

## الفكرة

نحتاج لاحقًا إلى طبقة ربط بين مركز التحليل والاختبارات وبين محرك الـ Workflow الحالي.

الهدف ليس أن يقوم Assessment Center بإنشاء حالات أو برامج بشكل ثابت داخل الكود، بل أن يقترح تدخلات ذكية، ثم يتم ربط هذه التدخلات بخدمات و Workflows يحددها الأدمن.

## الاسم المقترح

قواعد التدخل الذكي  
Smart Intervention Rules

## التدفق المقترح

Assessment Center
→ يكتشف ضعف أو خطر أو حاجة متابعة
→ يولد توصية أو تدخل مقترح
→ الموجه يراجع الاقتراح
→ الموجه يضغط إنشاء حالة أو إنشاء برنامج
→ النظام يستخدم Workflow محدد مسبقًا من إعدادات الأدمن

## أمثلة القواعد

### ضعف طالب فردي

الشرط:
- متوسط الطالب أقل من 60%
- أو الطالب ضعيف في مادتين أو أكثر

الإجراء:
- إنشاء حالة متابعة

الخدمة المقترحة:
- متابعة الطلاب

Workflow المقترح:
- حالة ضعف دراسي

البيانات التي تعبأ تلقائيًا:
- الطالب
- الصف
- الفصل
- المواد الضعيفة
- متوسط الطالب
- سبب الحالة
- التوصية العلاجية

### ضعف فصل كامل

الشرط:
- متوسط الفصل أقل من المتوسط العام
- أو وجود عدد كبير من الطلاب المتعثرين في مادة محددة

الإجراء:
- إنشاء برنامج علاجي جماعي

الخدمة المقترحة:
- البرامج الإرشادية

Workflow المقترح:
- برنامج علاجي لمادة دراسية

البيانات التي تعبأ تلقائيًا:
- الصف
- الفصل
- المادة
- عدد الطلاب المتعثرين
- متوسط الفصل
- التوصية الجماعية

## مراحل التنفيذ لاحقًا

1. مرحلة الاقتراح فقط:
يعرض النظام توصيات وتدخلات مقترحة بدون إنشاء أي شيء.

2. مرحلة الإنشاء اليدوي الذكي:
الموجه يضغط زر إنشاء حالة أو برنامج، والنظام يعبئ البيانات تلقائيًا.

3. مرحلة إعدادات الأدمن:
الأدمن يربط كل نوع تدخل بخدمة و Workflow محدد.

4. مرحلة الأتمتة الاختيارية:
الأدمن يستطيع تفعيل إنشاء تدخلات تلقائية لبعض القواعد فقط.

## قواعد مهمة

- لا يتم إنشاء حالة تلقائيًا بدون مراجعة الموجه في البداية.
- لا يتم ربط Assessment Center بخدمة واحدة فقط.
- الربط يجب أن يكون مرنًا مع:
  - متابعة الطلاب
  - البرامج الإرشادية
  - الخدمات الإرشادية المقدمة للطلاب
  - أي Workflow مستقبلي
- أي إنشاء حالة أو برنامج يجب أن يسجل في Audit Log.
- أي زر حساس يجب أن يستخدم SmartFeedbackModal.
